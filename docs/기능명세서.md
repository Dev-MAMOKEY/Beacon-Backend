## 1. 용어 정의

개발 과정에서 혼선이 없도록 핵심 용어를 먼저 정의합니다.

**Club(동아리)**: 이 시스템을 사용하는 하나의 동아리 단위입니다. 하나의 Club 안에 여러 Member가 속합니다.

**Member(멤버)**: Club에 소속된 사용자입니다. 역할은 `MEMBER`와 `ADMIN` 두 가지로 나뉩니다.

**Session(세션)**: 출석을 받는 하나의 이벤트 단위입니다. 예를 들어 "3월 20일 정기모임"이 하나의 세션입니다. 한 Club에서 동시에 활성화(ACTIVE)된 세션은 단 하나뿐입니다.

**AttendanceCode(출석 비밀번호)**: 세션이 시작(ACTIVE)될 때 자동 생성되는 4자리 랜덤 숫자입니다. 관리자 화면에만 표시되며, 세션이 종료되면 자동 만료됩니다.

**Beacon(비콘)**: 활동 장소에 설치된 ESP32 기기입니다. BLE 신호를 지속 송출하며, 앱에서 이 신호를 감지해야만 출석 비밀번호 입력 UI가 열립니다.

**AttendanceRecord(출석 기록)**: 특정 세션에서 특정 멤버의 출석 상태(출석/지각/결석/기타)를 저장하는 레코드입니다. 세션이 종료될 때 아직 출석하지 않은 멤버에 대해 자동으로 `ABSENT` 레코드가 생성됩니다.

## 2. 시스템 아키텍처 개요

전체 시스템은 4개의 레이어로 구성됩니다.

**Flutter 앱**은 동아리원과 관리자가 공통으로 사용하는 모바일 클라이언트입니다. BLE 스캔을 담당하며, 역할에 따라 UI가 분기됩니다.

**React 웹**은 관리자 전용 대시보드입니다. 통계 차트, 반복 세션 생성, CSV/Excel 내보내기 등 데이터 집약적인 기능을 제공합니다.

**Spring Boot 서버**는 REST API를 제공하는 백엔드입니다. 모든 비즈니스 로직과 데이터 검증은 서버에서 처리합니다. 앱과 웹 모두 이 서버와 통신합니다.

**ESP32 비콘**은 BLE 신호를 송출하는 하드웨어입니다. 서버와 직접 통신하지 않으며, 오직 BLE 패킷을 공간에 브로드캐스트하는 역할만 합니다. 앱이 이 신호를 수신하여 서버에 보고합니다.

## 3. 공통 규칙

### 3-1. 인증 방식

모든 API 요청(로그인/회원가입 제외)은 HTTP 헤더에 JWT 토큰을 포함해야 합니다. 형식은 `Authorization: Bearer {accessToken}`입니다.

Access Token의 유효기간은 1시간이며, Refresh Token의 유효기간은 30일입니다. Refresh Token은 서버 DB에 저장하여 강제 로그아웃(토큰 무효화)이 가능하도록 합니다.

### 3-2. 응답 형식

모든 API 응답은 아래 구조를 따릅니다.

```json
{
  "success": true,
  "data": { ... },
  "error": null,
  "timestamp": "2025-03-20T09:41:00Z"
}
```

실패 시에는 `success: false`, `data: null`이 되고 `error` 필드에 코드와 메시지가 담깁니다.

### 3-3. 시간대

모든 시간은 UTC로 저장하고, 클라이언트에서 로컬 시간대(KST = UTC+9)로 변환하여 표시합니다.

### 3-4. 소프트 삭제 정책

멤버 제명, 세션 삭제 등 대부분의 삭제 작업은 실제로 DB 레코드를 지우지 않고 `deleted_at` 타임스탬프를 기록하는 소프트 삭제 방식을 사용합니다. 이는 데이터 복구 가능성과 감사 추적을 위한 설계입니다.

## 4. 인증 및 회원 관리

### 4-1. 회원가입

사용자가 학번, 이름, 비밀번호를 입력하여 계정을 생성합니다. 이 단계에서는 아직 어떤 동아리에도 속하지 않은 상태입니다. 동아리 소속은 이후 초대코드 입력 단계에서 결정됩니다.

**입력 유효성 검증 규칙**으로는 학번은 영문/숫자 조합 4~20자 이내이며 중복 불가합니다. 비밀번호는 최소 8자 이상으로, 영문과 숫자를 각각 하나 이상 포함해야 합니다. 이름은 2~20자 이내 한글 또는 영문이어야 합니다.

**처리 흐름**은 입력 유효성 검증 → 학번 중복 확인 → 비밀번호 bcrypt 해싱(cost factor 10) → `member` 테이블에 레코드 생성 → 이메일 인증 없이 즉시 사용 가능 상태로 처리합니다.

### 4-2. 로그인

학번과 비밀번호로 로그인합니다. 성공 시 Access Token과 Refresh Token을 응답합니다.

로그인 실패 횟수 제한은 MVP에서는 구현하지 않으며, 추후 보안 강화 시 추가합니다.

### 4-3. 토큰 재발급

Access Token이 만료된 경우, Refresh Token을 사용해 새로운 Access Token을 발급받습니다. Refresh Token 자체가 만료된 경우에는 재로그인이 필요합니다.

### 4-4. 로그아웃

서버의 Refresh Token 레코드를 무효화(`revoked_at` 설정)합니다. 클라이언트는 저장된 토큰을 삭제합니다.

### 4-5. 비밀번호 변경

현재 비밀번호 확인 후 새 비밀번호로 변경합니다. 변경 시 해당 멤버의 모든 Refresh Token을 무효화하여 다른 기기에서 강제 로그아웃되도록 합니다.

### 4-6. 내 정보 수정

이름과 알림 설정을 변경할 수 있습니다. 학번은 변경 불가합니다.

## 5. 동아리 및 초대코드

### 5-1. 동아리 생성

인증된 멤버는 `POST /clubs/create`로 새 동아리를 만들 수 있습니다. 생성한 멤버는 자동으로 해당 동아리의 `ADMIN` 역할을 부여받습니다. 개발/테스트 환경에서는 서버 기동 시 시드(seed) 동아리가 자동 생성됩니다.

한 사용자는 여러 동아리를 만들거나 가입할 수 있는 구조이나, MVP에서는 단일 동아리 사용을 기본 전제로 합니다.

### 5-2. 초대코드 입력 (동아리 가입)

회원가입 후 로그인한 상태에서 관리자에게 받은 4자리 초대코드를 입력합니다. 유효한 코드인 경우 해당 동아리의 `MEMBER` 역할로 등록됩니다.

**처리 흐름**은 코드 유효성 확인(존재 여부 + 무효화 여부) → 이미 해당 동아리에 속한 멤버인지 확인 → `club_member` 테이블에 레코드 생성 (role = `MEMBER`) → 동아리 홈 화면으로 이동 순으로 진행됩니다.

한 사용자는 여러 동아리에 가입할 수 있는 구조이나, MVP에서는 단일 동아리만 지원합니다.

### 5-3. 초대코드 발급 (관리자)

관리자가 초대코드를 새로 발급합니다. 발급 시 4자리 랜덤 영숫자 코드가 생성됩니다. 동일한 동아리에 대해 유효한 코드는 하나만 존재합니다. 새 코드를 발급하면 이전 코드는 자동으로 무효화됩니다.

### 5-4. 초대코드 수동 무효화 (관리자)

코드가 유출됐다고 판단될 때 관리자가 즉시 무효화합니다. 무효화된 코드로는 더 이상 가입이 불가능합니다. 무효화 후에는 필요 시 새 코드를 발급해야 합니다.

### 5-5. 동아리 정보 수정 (관리자)

동아리 이름과 설명을 수정할 수 있습니다.

## 6. 비콘 설정

### 6-1. 비콘 설정 값 정의

비콘의 동작과 출석 판정 기준을 설정합니다. 설정 값은 Club 단위로 저장됩니다.

**RSSI 임계값**은 비콘 감지 유효 거리를 결정하는 신호 강도 기준입니다. RSSI는 음수 값으로, 0에 가까울수록 가깝습니다. 기본값은 `-70 dBm`이며, 이 값보다 신호가 강할 때(예: -60)만 유효 감지로 판정합니다. 관리자가 앱 또는 웹에서 슬라이더로 조정할 수 있습니다.

**지각 기준 시간**은 세션 시작 후 몇 분 이내 출석해야 "출석"으로 인정되는지를 설정합니다. 기본값은 10분이며, 이를 초과하면 "지각"으로 처리됩니다.

**스캐너 지속 시간**은 앱이 BLE 스캔을 유지하는 최대 시간입니다. 기본값은 30초입니다.

**신호 안정화 임계 시간**은 비콘 신호가 몇 초 이상 지속 감지되어야 출석 UI를 활성화할지 결정합니다. 기본값은 3초입니다. 이 값을 두는 이유는 경계 지점에서 신호가 깜빡이는 현상(Flickering)을 방지하기 위함입니다.

### 6-2. 비콘 UUID 등록

비콘 기기의 고유 식별자(UUID)를 Club에 등록합니다. 앱은 이 UUID와 일치하는 BLE 신호만 유효한 비콘 감지로 처리합니다. 이로써 인근의 다른 BLE 기기가 오작동을 유발하는 것을 방지합니다.

## 7. 세션 관리

### 7-1. 세션 생성 (관리자)

새로운 출석 세션을 생성합니다. 세션은 `SCHEDULED(예정)`, `ACTIVE(진행 중)`, `ENDED(종료)` 세 가지 상태 중 하나를 가집니다.

**입력 항목**으로는 세션 이름(예: "3월 20일 정기모임"), 예정 시작 시간, 예정 종료 시간을 입력합니다. 예정 시간은 참고용이며 실제 시작/종료는 관리자가 수동으로 수행합니다.

**중복 생성 방지 규칙**: 현재 `ACTIVE` 상태의 세션이 존재하면 새 세션 생성이 차단됩니다. 서버는 이 경우 `SESSION_ALREADY_ACTIVE` 에러를 반환합니다.

### 7-2. 세션 시작 (관리자)

`SCHEDULED` 상태의 세션을 `ACTIVE`로 전환합니다. 이 시점에 출석 비밀번호가 자동 생성됩니다.

**비밀번호 생성 규칙**은 4자리 랜덤 숫자(0000~9999)를 생성합니다. 생성된 비밀번호는 `session` 테이블의 `attendance_code` 컬럼에 저장됩니다. 보안을 위해 평문이 아닌 해시로 저장하고, 관리자 응답 시에만 평문을 반환합니다.

시작 시각(`started_at`)을 현재 시간으로 기록합니다.

### 7-3. 세션 종료 (관리자)

`ACTIVE` 상태의 세션을 `ENDED`로 전환합니다. 이 시점에 아직 출석 기록이 없는 모든 멤버에 대해 자동으로 `ABSENT` 레코드를 생성합니다. 이 처리는 트랜잭션 내에서 원자적으로(Atomically) 수행되어야 합니다. 종료 시각(`ended_at`)을 현재 시간으로 기록합니다.

### 7-4. 세션 수정 (관리자)

세션 이름과 예정 시간을 수정합니다. `ENDED` 상태의 세션은 수정이 불가능합니다.

### 7-5. 세션 삭제 (관리자)

세션을 소프트 삭제합니다. `ACTIVE` 상태의 세션은 삭제가 불가능하며, 먼저 종료해야 합니다. 삭제된 세션에 연결된 `attendance_record`는 함께 소프트 삭제됩니다.

### 7-6. 세션 목록 조회

관리자는 해당 Club의 전체 세션 목록을 조회할 수 있습니다. 최신 세션이 상단에 표시되며, 상태별 필터링이 가능합니다.

---

## 8. 출석 체크 (핵심 플로우)

이 섹션은 시스템의 가장 핵심적인 기능으로, 구현 시 가장 주의가 필요한 부분입니다.

### 8-1. 앱 측 BLE 스캔 로직

앱이 홈 화면에 진입하면 BLE 스캔을 시작합니다. 스캔은 백그라운드가 아닌 포그라운드 상태에서만 동작합니다.

**비콘 감지 판정 과정**은 다음과 같습니다. 먼저 수신된 BLE 패킷의 UUID가 등록된 비콘 UUID와 일치하는지 확인합니다. 그런 다음 수신 신호 강도(RSSI)가 설정된 임계값보다 강한지 확인합니다. 이 두 조건을 모두 만족한 상태가 설정된 안정화 임계 시간(기본 3초) 이상 지속되면 비콘 감지 완료로 판정하고 비밀번호 입력 UI를 활성화합니다.

**비콘 미감지 시 처리**로는 블루투스가 꺼진 경우 설정 화면으로 이동하는 버튼을 제공합니다. 비콘이 범위 밖인 경우 "출석 가능 구역에 있지 않습니다" 안내와 재시도 버튼을 제공합니다.

### 8-2. 비밀번호 입력 및 출석 처리

비콘이 감지된 상태에서 사용자가 4자리 비밀번호를 입력하고 출석 버튼을 누릅니다.

**서버 측 검증 과정**은 다음과 같습니다. 먼저 요청자가 해당 Club의 멤버인지 확인합니다. 현재 `ACTIVE` 세션이 존재하는지 확인합니다. 입력된 비밀번호가 세션의 `attendance_code`와 일치하는지 확인합니다. 해당 멤버가 이미 이 세션에 출석 기록이 있는지 확인하여 중복 출석을 방지합니다.

**출석 상태 자동 판정**은 세션의 `started_at`으로부터 경과 시간을 계산합니다. 경과 시간이 지각 기준 시간(기본 10분) 이내이면 `PRESENT(출석)`로 기록하고, 초과이면 `LATE(지각)`으로 기록합니다.

**처리 성공 시** `attendance_record` 테이블에 레코드를 삽입하고, 출석 상태와 체크 시각을 포함한 응답을 반환합니다. 앱은 "출석 완료" 화면을 표시합니다.

### 8-3. 출석 처리 시의 동시성 처리

같은 세션에 여러 멤버가 동시에 출석을 시도하는 경우를 고려해야 합니다. `attendance_record` 테이블에 `(session_id, member_id)` 복합 유니크 제약을 설정하여 DB 레벨에서 중복 삽입을 방지합니다. 서버는 유니크 제약 위반 시 `ALREADY_CHECKED_IN` 에러를 반환합니다.

---

## 9. 출석 상태 관리

### 9-1. 출석 상태 정의

출석 상태는 `PRESENT(출석)`, `LATE(지각)`, `ABSENT(결석)`, `ETC(기타)` 네 가지입니다.

`ETC(기타)`는 시스템이 자동으로 부여하지 않으며, 오직 관리자만 수동으로 변경할 수 있습니다. 병결, 공결 등 특수 사유가 있는 경우 사용합니다.

### 9-2. 출석 상태 수동 변경 (관리자)

관리자는 세션 종료 후에도 언제든지 멤버의 출석 상태를 변경할 수 있습니다. 변경 시 사유 메모를 함께 입력할 수 있으며, 사유는 `attendance_record.admin_note` 컬럼에 저장됩니다. 변경 이력은 추적하지 않습니다(MVP 기준. 추후 감사 로그 추가 가능).

### 9-3. 수동 출석 처리 (관리자)

세션이 진행 중일 때 특정 멤버를 관리자가 직접 출석 처리할 수 있습니다. 예를 들어 비콘 오작동으로 출석 처리가 안 된 경우 등에 활용합니다. 수동 처리된 출석은 `is_manual` 플래그를 `true`로 기록합니다.

### 9-4. 출석률 계산 규칙

출석률은 다음 공식으로 계산합니다.

```
출석률 = (PRESENT + LATE + ETC 레코드 수) ÷ (해당 멤버의 전체 세션 참여 수) × 100
```

계산에서 제외되는 케이스는 해당 멤버가 동아리에 가입하기 전에 열린 세션의 레코드입니다. 즉, 동아리에 가입한 날짜 이후의 세션만 분모에 포함됩니다. 이는 신규 멤버가 불이익을 받지 않도록 하기 위한 설계입니다.

---

## 10. 멤버 관리

### 10-1. 멤버 목록 조회 (관리자)

해당 Club의 전체 멤버 목록을 조회합니다. 각 멤버의 이름, 학번, 역할, 전체 출석률을 함께 반환합니다. 이름 또는 학번으로 검색이 가능합니다.

### 10-2. 역할 변경 (관리자)

멤버의 역할을 `MEMBER`에서 `ADMIN`으로, 또는 `ADMIN`에서 `MEMBER`로 변경합니다. 자기 자신의 역할은 변경할 수 없습니다. (실수로 Admin 권한을 스스로 내리는 상황 방지)

### 10-3. 멤버 제명 (관리자)

멤버를 동아리에서 제명합니다. `club_member` 테이블의 `deleted_at`을 현재 시간으로 설정하는 소프트 삭제 방식입니다. 제명된 멤버는 앱을 새로고침 시 동아리 접근이 차단됩니다. 제명된 멤버의 과거 출석 기록은 보존됩니다(통계 데이터의 일관성 유지를 위해). 제명된 멤버가 다시 가입하려면 초대코드를 다시 입력해야 하며, 이 경우 새로운 `club_member` 레코드가 생성됩니다.

## 11. 통계 및 데이터 내보내기

### 11-1. 개인 출석 기록 조회 (동아리원)

로그인한 멤버 자신의 출석 기록을 조회합니다. 캘린더 뷰용 월별 데이터와 상태별 횟수 요약, 전체 출석률을 반환합니다.

### 11-2. 전체 출석 현황 조회 (관리자 앱)

특정 세션의 전체 멤버 출석 현황을 조회합니다. 상태별(출석/지각/결석/기타) 필터링이 가능합니다. 실시간으로 확인할 수 있도록 클라이언트는 30초 간격으로 폴링하거나, 서버가 WebSocket/SSE를 지원하는 경우 실시간 Push를 활용합니다(MVP에서는 폴링 방식 우선 구현).

### 11-3. 통계 데이터 조회 (웹 대시보드)

기간별 출석률 추이, 멤버별 출석률 비교, 상태별 분포 비율 데이터를 집계하여 반환합니다. 서버 측에서 집계 쿼리를 실행하여 가공된 데이터를 반환합니다.

### 11-4. CSV 내보내기 (웹 전용)

기간과 멤버를 필터링하여 출석 데이터를 CSV 형식으로 다운로드합니다. 컬럼은 멤버명, 학번, 세션명, 날짜, 출석 상태, 사유 메모 순서로 구성됩니다.

### 11-5. Excel 내보내기 (웹 전용)

CSV와 동일한 데이터를 Excel(.xlsx) 형식으로 다운로드합니다. 출석 상태에 따라 셀 배경색이 자동 적용됩니다(출석: 초록, 지각: 노랑, 결석: 빨강, 기타: 파랑).

## 12. 푸시 알림

### 12-1. 알림 유형

세션 시작 알림은 관리자가 세션을 `ACTIVE`로 전환할 때 해당 Club의 모든 멤버(관리자 포함)에게 발송됩니다. 알림 내용은 "'{세션명}' 출석 체크가 시작되었습니다. 지금 출석해주세요!" 형식입니다.

출석 완료 알림은 멤버가 성공적으로 출석 처리된 후 해당 멤버에게만 발송됩니다. 알림 내용은 "'{세션명}' 출석이 완료되었습니다. ({상태})" 형식입니다.

### 12-2. FCM 토큰 관리

앱 최초 실행 시 FCM 토큰을 서버에 등록합니다. 토큰 갱신 시 자동으로 서버에 업데이트합니다. 멤버가 알림 설정에서 알림을 끄면 서버에서 해당 토큰을 비활성화합니다.

## 13. 웹 대시보드 전용 기능

### 13-1. 반복 세션 생성

매주 특정 요일과 시간에 반복되는 세션을 한 번에 일괄 생성합니다. 예를 들어 "매주 목요일 10:00 ~ 13:00, 3월 ~ 6월" 설정 시 해당 기간의 모든 목요일에 대해 세션 레코드를 생성합니다. 각 세션은 독립적인 레코드로 저장되며, 일괄 생성 후 개별 수정이 가능합니다.

### 13-2. 일괄 상태 변경

테이블에서 여러 멤버를 선택하여 한 번에 출석 상태를 변경합니다. 예를 들어 특정 날 공식 행사로 전원 공결 처리가 필요한 경우 활용합니다.

### 13-3. 실시간 피드

웹 대시보드 우측 패널에 출석 이벤트가 발생할 때마다 실시간으로 표시됩니다. "김민준 님이 출석했습니다 (오전 10:03)" 형태로 표시됩니다. WebSocket 또는 Server-Sent Events(SSE)를 활용합니다.

## 14. DB 테이블 스키마

데이터베이스는 MySQL 8.0 이상을 기준으로 설계합니다. 모든 테이블은 `id`, `created_at`, `updated_at`을 기본으로 포함합니다.

---

### 14-1. member (회원)

사용자 계정을 저장하는 테이블입니다. 동아리 소속 정보는 별도의 `club_member` 테이블에서 관리합니다.

```sql
CREATE TABLE member (
    id              BIGINT          NOT NULL AUTO_INCREMENT,
    student_id      VARCHAR(20)     NOT NULL UNIQUE,         -- 학번 (로그인 ID)
    name            VARCHAR(50)     NOT NULL,                -- 이름
    password_hash   VARCHAR(255)    NOT NULL,                -- bcrypt 해시
    fcm_token       VARCHAR(255)    NULL,                    -- 푸시 알림용 FCM 토큰
    push_enabled    BOOLEAN         NOT NULL DEFAULT TRUE,   -- 알림 수신 여부
    created_at      DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at      DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
    deleted_at      DATETIME(6)     NULL,                    -- 소프트 삭제 (계정 탈퇴)

    PRIMARY KEY (id),
    INDEX idx_member_student_id (student_id)
);
```

---

### 14-2. refresh_token (리프레시 토큰)

JWT 리프레시 토큰을 서버에 저장하여 강제 로그아웃이 가능하도록 합니다.

> **MVP 구현 노트 (DEC-3, 백엔드 #37 결정)**: 현재 구현은 아래 별도 테이블 대신 `member` 테이블 컬럼에 리프레시 토큰을 직접 저장합니다(회원당 1개). 별도 `refresh_token` 테이블(다기기 세션·토큰별 무효화·감사 추적)은 **추후 확장** 항목이며, MVP에서는 도입하지 않기로 결정했습니다.

```sql
CREATE TABLE refresh_token (
    id          BIGINT          NOT NULL AUTO_INCREMENT,
    member_id   BIGINT          NOT NULL,
    token       VARCHAR(512)    NOT NULL UNIQUE,     -- JWT 리프레시 토큰 문자열
    expires_at  DATETIME(6)     NOT NULL,            -- 만료 시각
    revoked_at  DATETIME(6)     NULL,                -- 무효화 시각 (null이면 유효)
    created_at  DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),

    PRIMARY KEY (id),
    FOREIGN KEY (member_id) REFERENCES member(id),
    INDEX idx_refresh_token_token (token),
    INDEX idx_refresh_token_member (member_id)
);
```

---

### 14-3. club (동아리)

동아리 정보를 저장합니다.

> **구현 노트**: 실제 `club` 엔티티에는 아래 스키마 외에 비콘 연동용 필드 `fixed_uuid`(등록 비콘 UUID, §6-2 대응)와 `psk`(pre-shared key, 비콘 보안용)가 추가되어 있으며 동아리 생성 시 자동 부여됩니다. 이 필드들의 최종 정의·용도는 비콘 설정 도메인 작업(백엔드 #32)에서 정리합니다.

```sql
CREATE TABLE club (
    id          BIGINT          NOT NULL AUTO_INCREMENT,
    name        VARCHAR(100)    NOT NULL,            -- 동아리 이름
    description VARCHAR(500)    NULL,                -- 동아리 소개
    created_at  DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at  DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
    deleted_at  DATETIME(6)     NULL,

    PRIMARY KEY (id)
);
```

---

### 14-4. club_member (동아리-회원 소속)

한 사용자가 여러 동아리에 속할 수 있는 다대다 관계를 처리하는 중간 테이블입니다. 역할 정보도 이 테이블에서 관리합니다.

```sql
CREATE TABLE club_member (
    id          BIGINT          NOT NULL AUTO_INCREMENT,
    club_id     BIGINT          NOT NULL,
    member_id   BIGINT          NOT NULL,
    role        ENUM('MEMBER', 'ADMIN') NOT NULL DEFAULT 'MEMBER',
    joined_at   DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),  -- 가입 날짜 (출석률 계산 기준점)
    created_at  DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at  DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
    deleted_at  DATETIME(6)     NULL,                -- 소프트 삭제 (제명 또는 탈퇴)

    PRIMARY KEY (id),
    UNIQUE KEY uq_club_member (club_id, member_id),  -- 동일 동아리 중복 가입 방지
    FOREIGN KEY (club_id) REFERENCES club(id),
    FOREIGN KEY (member_id) REFERENCES member(id),
    INDEX idx_club_member_club (club_id),
    INDEX idx_club_member_member (member_id)
);
```

---

### 14-5. invite_code (초대코드)

동아리별 초대코드를 저장합니다. 한 동아리에 유효한 코드는 항상 하나입니다.

```sql
CREATE TABLE invite_code (
    id          BIGINT          NOT NULL AUTO_INCREMENT,
    club_id     BIGINT          NOT NULL,
    code        VARCHAR(10)     NOT NULL UNIQUE,     -- 4자리 랜덤 영숫자
    revoked_at  DATETIME(6)     NULL,                -- 무효화 시각 (null이면 유효)
    created_by  BIGINT          NOT NULL,            -- 발급한 관리자의 member_id
    created_at  DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),

    PRIMARY KEY (id),
    FOREIGN KEY (club_id) REFERENCES club(id),
    FOREIGN KEY (created_by) REFERENCES member(id),
    INDEX idx_invite_code_club (club_id),
    INDEX idx_invite_code_code (code)
);
```

---

### 14-6. beacon_config (비콘 설정)

Club별 비콘 동작 설정 값을 저장합니다. Club당 1개의 레코드만 존재합니다.

```sql
CREATE TABLE beacon_config (
    id                      BIGINT          NOT NULL AUTO_INCREMENT,
    club_id                 BIGINT          NOT NULL UNIQUE,
    beacon_uuid             VARCHAR(50)     NOT NULL,           -- 등록된 비콘 UUID
    rssi_threshold          INT             NOT NULL DEFAULT -70,  -- 유효 감지 RSSI 임계값 (dBm)

    scan_duration_seconds   INT             NOT NULL DEFAULT 30,   -- 스캔 지속 시간 (초)
    signal_stable_seconds   INT             NOT NULL DEFAULT 3,    -- 신호 안정화 임계 시간 (초)
    created_at              DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at              DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),

    PRIMARY KEY (id),
    FOREIGN KEY (club_id) REFERENCES club(id)
);
```

### 14-7. session (세션)

출석 이벤트 단위인 세션을 저장합니다.

```sql
CREATE TABLE session (
    id                  BIGINT          NOT NULL AUTO_INCREMENT,
    club_id             BIGINT          NOT NULL,
    name                VARCHAR(100)    NOT NULL,            -- 세션 이름 (예: 3월 20일 정기모임)
    status              ENUM('SCHEDULED', 'ACTIVE', 'ENDED') NOT NULL DEFAULT 'SCHEDULED',
    attendance_code     VARCHAR(10)     NULL,                -- 출석 비밀번호 (ACTIVE 상태일 때만 설정됨, bcrypt 해시로 저장)
    late_threshold_minutes INT          NOT NULL DEFAULT 10, -- 세션 생성 시점의 지각 기준 시간 스냅샷
    scheduled_start_at  DATETIME(6)     NULL,                -- 예정 시작 시각 (참고용)
    scheduled_end_at    DATETIME(6)     NULL,                -- 예정 종료 시각 (참고용)
    started_at          DATETIME(6)     NULL,                -- 실제 시작 시각 (출석/지각 판정 기준)
    ended_at            DATETIME(6)     NULL,                -- 실제 종료 시각
    created_by          BIGINT          NOT NULL,            -- 생성한 관리자의 member_id
    created_at          DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at          DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),
    deleted_at          DATETIME(6)     NULL,

    PRIMARY KEY (id),
    FOREIGN KEY (club_id) REFERENCES club(id),
    FOREIGN KEY (created_by) REFERENCES member(id),
    INDEX idx_session_club (club_id),
    INDEX idx_session_status (club_id, status)  -- 활성 세션 조회 최적화
);
```

`late_threshold_minutes`를 세션에도 저장하는 이유는 설정 변경 이후에도 과거 세션의 지각 기준이 유지되도록 하기 위한 스냅샷 방식입니다.

```sql
CREATE TABLE attendance_record (
    id              BIGINT          NOT NULL AUTO_INCREMENT,
    session_id      BIGINT          NOT NULL,

    created_at      DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6),
    updated_at      DATETIME(6)     NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6),

    PRIMARY KEY (id),
    UNIQUE KEY uq_attendance (session_id, member_id),   -- 동일 세션+멤버 중복 방지 (동시성 처리)

    INDEX idx_attendance_session (session_id),

```

## 16. 에러 코드 정의

모든 에러 응답은 아래 형식으로 반환됩니다.

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "INVALID_PASSWORD",
    "message": "비밀번호가 올바르지 않습니다."
  },
  "timestamp": "2025-03-20T09:41:00Z"
}
```

### 인증 관련 에러

`INVALID_CREDENTIALS`는 학번 또는 비밀번호가 틀린 경우입니다. `TOKEN_EXPIRED`는 Access Token이 만료된 경우입니다. `TOKEN_INVALID`는 토큰 형식이 잘못되었거나 서명이 유효하지 않은 경우입니다. `REFRESH_TOKEN_REVOKED`는 이미 무효화된 Refresh Token을 사용한 경우입니다.

### 권한 관련 에러

`FORBIDDEN`은 해당 리소스에 대한 권한이 없는 경우입니다. `NOT_CLUB_MEMBER`는 해당 동아리의 멤버가 아닌 경우입니다.

### 회원/동아리 관련 에러

`DUPLICATE_STUDENT_ID`는 이미 사용 중인 학번으로 회원가입을 시도한 경우입니다. `INVALID_INVITE_CODE`는 초대코드가 존재하지 않거나 무효화된 경우입니다. `ALREADY_CLUB_MEMBER`는 이미 해당 동아리의 멤버인 경우입니다.

### 세션 관련 에러

`SESSION_ALREADY_ACTIVE`는 이미 진행 중인 세션이 있어 새 세션을 만들 수 없는 경우입니다. `SESSION_NOT_ACTIVE`는 출석 체크를 시도했으나 현재 활성 세션이 없는 경우입니다. `SESSION_NOT_FOUND`는 해당 세션이 존재하지 않는 경우입니다.

### 출석 관련 에러

`INVALID_ATTENDANCE_CODE`는 입력한 비밀번호가 틀린 경우입니다. `ALREADY_CHECKED_IN`은 이미 해당 세션에 출석 처리된 경우입니다. `BEACON_NOT_DETECTED`는 비콘 신호 없이 출석을 시도한 경우입니다(서버 측에서는 검증 불가하므로 앱 측에서 사전 차단).

## 17. 화면별 페이지 기능 명세

이 섹션은 앱과 웹의 각 화면 단위로 표시 요소, 사용자 인터랙션, API 연결, 예외 처리를 상세히 정의합니다. 개발자와 디자이너가 화면을 구현할 때 이 섹션을 1차 참조 문서로 활용합니다.

각 화면 명세는 아래 구조로 작성합니다.

- **진입 조건**: 이 화면에 도달하기 위한 선행 조건
- **표시 요소**: 화면에 렌더링되는 모든 UI 컴포넌트와 데이터
- **사용자 액션**: 사용자가 수행할 수 있는 모든 인터랙션과 그 결과
- **API 호출**: 화면 진입 시 또는 액션에 의해 호출되는 API
- **예외 처리**: 오류 상황별 UI 처리 방식

---

### 17-1. 스플래시 / 온보딩

**진입 조건**: 앱 최초 실행 시 또는 로컬 저장소에 유효한 토큰이 없을 때 진입합니다.

**표시 요소**: 앱 로고와 서비스 이름("마모키")을 중앙에 표시합니다. 약 1.5초간 스플래시를 보여준 후 자동으로 다음 화면으로 전환합니다.

**사용자 액션 및 분기**: 로컬 저장소에 Refresh Token이 존재하면 토큰 유효성 검증 API를 호출합니다. 토큰이 유효하면 동아리 소속 여부에 따라 홈 화면 또는 초대코드 입력 화면으로 이동합니다. 토큰이 만료되었거나 없으면 로그인 화면으로 이동합니다.

**API 호출**: `POST /auth/refresh` (저장된 Refresh Token으로 Access Token 재발급 시도)

---

### 17-2. 회원가입 화면

**진입 조건**: 로그인 화면에서 "회원가입" 버튼을 탭했을 때 진입합니다.

**표시 요소**: 학번 입력 필드, 이름 입력 필드, 비밀번호 입력 필드, 비밀번호 확인 입력 필드, 회원가입 버튼, 하단에 "이미 계정이 있으신가요? 로그인" 링크를 표시합니다. 각 입력 필드 하단에는 실시간 유효성 검증 메시지 영역이 있습니다.

**사용자 액션**:

회원가입 버튼을 탭하면 클라이언트 측 유효성 검증을 먼저 수행합니다. 학번은 4~20자 영문/숫자 조합인지 확인하고, 비밀번호는 8자 이상 영문+숫자 포함인지 확인하며, 비밀번호 확인 필드가 일치하는지 검사합니다. 모든 검증 통과 시 회원가입 API를 호출합니다. 성공하면 자동으로 로그인 처리 후 초대코드 입력 화면으로 이동합니다.

비밀번호 필드는 기본적으로 마스킹 처리되며, 우측 아이콘 탭으로 표시/숨김을 전환할 수 있습니다.

**API 호출**: `POST /auth/signup`

**예외 처리**: 학번 중복(`DUPLICATE_STUDENT_ID`) 시 학번 필드 하단에 "이미 사용 중인 학번입니다" 메시지를 인라인으로 표시합니다. 네트워크 오류 시 토스트 메시지로 안내합니다.

---

### 17-3. 로그인 화면

**진입 조건**: 앱 첫 실행 시(토큰 없음), 또는 회원가입 화면의 로그인 링크를 탭했을 때 진입합니다.

**표시 요소**: 앱 로고(소형), 학번 입력 필드, 비밀번호 입력 필드, 로그인 버튼, "회원가입" 링크를 표시합니다.

**사용자 액션**:

로그인 버튼을 탭하면 두 필드 모두 값이 있는지 확인 후 API를 호출합니다. 성공 시 Access Token과 Refresh Token을 로컬 보안 저장소(Flutter Secure Storage)에 저장합니다. 이후 해당 사용자가 동아리에 가입되어 있으면 홈 화면으로, 아직 가입하지 않았으면 초대코드 입력 화면으로 이동합니다.

**API 호출**: `POST /auth/login`

**예외 처리**: 인증 실패(`INVALID_CREDENTIALS`) 시 "학번 또는 비밀번호가 올바르지 않습니다" 메시지를 화면에 표시합니다. 개별 필드에 오류를 표시하지 않는 것이 보안상 권장 방식입니다(어느 필드가 틀렸는지 노출하지 않음).

---

### 17-4. 초대코드 입력 화면

**진입 조건**: 로그인 후 동아리 소속이 없는 사용자가 진입합니다. 스킵 불가 화면입니다.

**표시 요소**: 안내 텍스트("관리자에게 받은 초대코드를 입력해주세요"), 4자리 코드 입력 필드(영숫자, 자동 대문자 변환), 확인 버튼을 표시합니다.

**사용자 액션**:

확인 버튼 탭 시 API를 호출합니다. 성공 시 `club_member` 레코드가 생성되고 홈 화면으로 이동합니다. 4자리를 모두 입력하면 버튼이 자동 활성화되고, 미완성 상태에서는 버튼이 비활성화(disabled)됩니다.

**API 호출**: `POST /clubs/join` (body: `{ "inviteCode": "AB12" }`)

**예외 처리**: 유효하지 않은 코드(`INVALID_INVITE_CODE`) 시 "유효하지 않은 초대코드입니다. 관리자에게 다시 확인해주세요" 메시지를 표시하고 입력 필드를 초기화합니다.

---

### 17-5. 동아리원 홈 화면 (출석 체크)

이 화면은 앱의 핵심 화면으로, 진입 즉시 BLE 스캔을 시작합니다.

**진입 조건**: 로그인 + 동아리 소속이 있는 사용자가 하단 탭 "홈"을 탭했을 때 진입합니다.

**표시 요소**:

상단 영역에는 사용자 이름과 오늘 날짜를 표시합니다. 중앙에는 비콘 감지 상태 시각화 컴포넌트(동심원 애니메이션)를 배치합니다. 비콘 미감지 상태에서는 원이 회색으로 비활성화되고 "비콘을 찾는 중입니다..." 텍스트를 표시합니다. 비콘 감지 상태에서는 원이 초록색으로 활성화되고 비밀번호 입력 필드 4개가 나타납니다.

하단에는 이번 달 출석률, 지각 횟수, 결석 횟수를 요약 카드로 표시합니다.

**사용자 액션**:

비콘이 감지된 상태에서 4자리 비밀번호를 모두 입력하면 자동으로 출석 API가 호출됩니다. 별도의 확인 버튼 탭이 필요 없도록 4번째 자리 입력 즉시 API를 호출하는 방식이 UX상 자연스럽습니다. 출석 성공 시 출석 완료 화면(17-6)으로 전환합니다.

화면 진입 시 활성 세션 유무를 조회하여, 세션이 없으면 "현재 진행 중인 출석 세션이 없습니다" 상태를 표시합니다. 이 경우 비콘이 감지되더라도 비밀번호 입력 UI를 열지 않습니다.

**API 호출**:
- 화면 진입 시: `GET /clubs/{clubId}/sessions/active` (활성 세션 조회)
- 출석 처리 시: `POST /clubs/{clubId}/sessions/{sessionId}/attendance` (body: `{ "code": "7329" }`)
- 요약 데이터: `GET /clubs/{clubId}/members/me/records?period=current_month`

**예외 처리**:

블루투스가 꺼진 경우 "블루투스가 꺼져 있습니다" 안내와 설정 화면으로 이동하는 버튼을 표시합니다. 비콘이 감지되지 않는 경우 비콘 오류 화면(17-7)을 모달로 표시합니다. 비밀번호 불일치(`INVALID_ATTENDANCE_CODE`) 시 입력 필드를 진동 애니메이션과 함께 초기화하고 "비밀번호가 올바르지 않습니다" 메시지를 표시합니다. 이미 출석된 경우(`ALREADY_CHECKED_IN`) "이미 출석 처리되었습니다" 토스트를 표시합니다.

**비콘 범위 이탈 상태**: "출석 가능 구역에 있지 않습니다" 텍스트와 "다시 시도" 버튼을 표시합니다. 다시 시도 버튼 탭 시 BLE 스캔을 재시작합니다.

**서버 통신 실패 상태**: 출석 API 호출 실패 시 토스트 메시지로 "일시적인 오류가 발생했습니다" 안내 후 자동으로 1회 재시도합니다. 재시도도 실패하면 "잠시 후 다시 시도해주세요" 메시지와 수동 재시도 버튼을 표시합니다.

**사용자 액션**:

월 이동 화살표 탭 시 해당 월 데이터를 새로 조회합니다. 미래 월로는 이동하지 않도록 다음달 화살표를 현재 월에서 비활성화합니다. 특정 날짜 셀 탭 시 해당 날짜의 세션 상세 정보를 하단 시트(Bottom Sheet)로 표시합니다.

**API 호출**: `GET /clubs/{clubId}/members/me/records?year=2025&month=3`

### 17-11. 관리자 세션관리 화면

**진입 조건**: `ADMIN` 역할 사용자만 접근 가능한 하단 탭 "관리" → 서브탭 "세션관리"입니다.

**표시 요소**:

상단에 "새 세션 만들기" 버튼을 고정 배치합니다. 버튼 하단에 세션 목록 카드를 최신순으로 나열합니다. 각 세션 카드에는 세션 이름, 예정 시간, 상태 배지(예정/진행 중/종료), 그리고 `ACTIVE` 상태인 경우 출석 비밀번호를 표시합니다. 상태별 필터 탭(전체/예정/진행 중/종료)을 목록 상단에 배치합니다.

`ACTIVE` 세션 카드는 목록 최상단에 고정되며 시각적으로 강조(초록 테두리)됩니다. `ACTIVE` 세션 카드에는 "종료" 버튼이 추가로 표시되고, `SCHEDULED` 세션 카드에는 "시작" 버튼이 표시됩니다.

**사용자 액션**:

새 세션 만들기 버튼 탭 시 세션 생성/수정 화면(17-12)으로 이동합니다. 단, 현재 `ACTIVE` 세션이 존재하면 버튼이 비활성화되고 "진행 중인 세션이 있습니다. 먼저 종료해주세요" 툴팁을 표시합니다.

시작 버튼 탭 시 확인 다이얼로그("세션을 시작하면 출석 비밀번호가 자동 생성됩니다. 시작하시겠습니까?") 표시 후 세션 시작 API를 호출합니다. 성공 시 카드가 `ACTIVE` 상태로 전환되며 비밀번호가 노출됩니다.

종료 버튼 탭 시 확인 다이얼로그("세션을 종료하면 미출석 멤버는 자동으로 결석 처리됩니다. 종료하시겠습니까?") 표시 후 세션 종료 API를 호출합니다.

세션 카드 탭(버튼 영역 외) 시 세션 생성/수정 화면으로 이동합니다. `ENDED` 세션은 수정이 불가하므로 탭 시 상세 조회 모드(읽기 전용)로 열립니다.

**API 호출**:
- 진입 시: `GET /clubs/{clubId}/sessions`
- 세션 시작: `POST /clubs/{clubId}/sessions/{sessionId}/start`
- 세션 종료: `POST /clubs/{clubId}/sessions/{sessionId}/end`

### 17-12. 세션 생성 / 수정 화면

**진입 조건**: 세션관리 화면에서 "새 세션 만들기" 버튼 탭 또는 기존 세션 카드 탭 시 진입합니다. 상단에 뒤로가기 버튼이 있습니다.

**표시 요소**: 세션 이름 입력 필드, 예정 시작 날짜/시간 선택기, 예정 종료 날짜/시간 선택기, 저장 버튼을 표시합니다. 수정 모드(`SCHEDULED` 상태)에서는 하단에 "세션 삭제" 버튼을 추가로 표시합니다.

**사용자 액션**:

저장 버튼 탭 시 세션 이름 필수 입력 검증 후 생성(`POST`) 또는 수정(`PATCH`) API를 호출합니다. 성공 시 세션관리 화면으로 돌아가며 목록이 갱신됩니다.

삭제 버튼 탭 시 "삭제된 세션은 복구할 수 없습니다. 삭제하시겠습니까?" 확인 다이얼로그 표시 후 삭제 API를 호출합니다.

**API 호출**:
- 생성: `POST /clubs/{clubId}/sessions`
- 수정: `PATCH /clubs/{clubId}/sessions/{sessionId}`
- 삭제: `DELETE /clubs/{clubId}/sessions/{sessionId}`

**사용자 액션**:

멤버 카드를 길게 누르거나(Long Press) 카드 우측 더보기 버튼(···) 탭 시 액션 시트가 열립니다. 액션 시트에는 "관리자로 변경" 또는 "동아리원으로 변경"(현재 역할에 따라 토글), "제명" 두 가지 옵션이 있습니다. 단, 본인 카드에서는 액션 시트가 열리지 않습니다(자기 자신 제명 및 역할 변경 방지).

역할 변경 탭 시 "역할을 변경하시겠습니까?" 확인 다이얼로그 후 API를 호출합니다. 제명 탭 시 "제명된 멤버는 동아리 접근이 차단됩니다. 제명하시겠습니까?" 확인 다이얼로그 후 API를 호출합니다. 제명 성공 시 목록에서 즉시 제거됩니다.

**API 호출**:
- 목록 조회: `GET /clubs/{clubId}/members`
- 역할 변경: `PATCH /clubs/{clubId}/members/{memberId}/role`
- 제명: `DELETE /clubs/{clubId}/members/{memberId}`

### 17-16. 관리자 설정 화면

**진입 조건**: 하단 탭 "마이" 또는 "관리" 탭 내 설정 아이콘을 탭했을 때 진입합니다.

**표시 요소**:

동아리 정보 섹션에는 동아리 이름 수정 필드와 설명 수정 필드가 있습니다.

초대코드 섹션에는 현재 유효한 초대코드 표시(없으면 "발급된 코드 없음")와 복사 버튼, 새 코드 발급 버튼, 무효화 버튼이 있습니다.

비콘 설정 섹션에는 비콘 UUID 입력 필드, RSSI 임계값 슬라이더(-40 ~ -90, 기본 -70), 지각 기준 시간 입력 필드(분), 신호 안정화 시간 입력 필드(초)가 있습니다.

**사용자 액션**:

각 섹션별로 독립적인 저장 버튼을 제공합니다. 초대코드 복사 버튼 탭 시 클립보드에 코드가 복사되고 "복사되었습니다" 토스트를 표시합니다. 새 코드 발급 탭 시 "기존 코드가 무효화됩니다. 발급하시겠습니까?" 확인 후 API를 호출합니다.

**API 호출**:
- 진입 시: `GET /clubs/{clubId}`, `GET /clubs/{clubId}/invite-code`, `GET /clubs/{clubId}/beacon-config`
- 동아리 정보 수정: `PATCH /clubs/{clubId}`
- 초대코드 발급: `POST /clubs/{clubId}/invite-code`
- 초대코드 무효화: `DELETE /clubs/{clubId}/invite-code`
- 비콘 설정 저장: `PUT /clubs/{clubId}/beacon-config`

### 17-17. 웹 대시보드 홈

**진입 조건**: 관리자가 웹 대시보드에 로그인 후 진입하는 기본 페이지입니다.

**레이아웃 구조**: 좌측에 고정 사이드바 네비게이션, 우측에 콘텐츠 영역으로 구성됩니다. 사이드바에는 대시보드 / 세션관리 / 출석현황 / 멤버&통계 / 설정 메뉴가 있습니다.

**표시 요소**:

콘텐츠 상단에 오늘 날짜와 현재 활성 세션 정보(없으면 "진행 중인 세션 없음")를 배치합니다.

요약 지표 카드 4개(오늘 출석 수 / 오늘 지각 수 / 전체 멤버 수 / 이번 달 평균 출석률)를 가로로 나열합니다.

중앙에 주간 출석률 추이 라인 차트를 배치합니다(최근 7일 기준).

우측 패널에 실시간 출석 피드를 표시합니다. 피드는 "김민준 님이 출석했습니다 (오전 10:03)" 형태로 최신 이벤트가 상단에 쌓이는 방식입니다. SSE(Server-Sent Events) 연결로 실시간 업데이트합니다.

**API 호출**:
- 요약 지표: `GET /clubs/{clubId}/stats/summary?date=today`
- 주간 차트: `GET /clubs/{clubId}/stats/trend?period=week`
- 실시간 피드: `GET /clubs/{clubId}/attendance/stream` (SSE 연결)

### 17-18. 웹 세션관리 페이지

**진입 조건**: 사이드바 "세션관리" 메뉴 클릭 시 진입합니다.

**표시 요소**:

상단에 "새 세션 만들기"와 "반복 세션 만들기"(웹 전용) 버튼을 배치합니다. 월 단위 달력 뷰를 기본으로 표시하며, 각 날짜 셀에 해당 날짜의 세션이 표시됩니다. 달력 우측에 세션 목록 패널을 함께 표시합니다.

**사용자 액션**:

달력의 날짜 셀 클릭 시 해당 날짜의 세션 목록을 우측 패널에 표시합니다. 세션 클릭 시 세션 상세/수정 모달이 열립니다. 반복 세션 만들기 클릭 시 반복 세션 생성 모달이 열립니다. 반복 세션 생성 모달에는 요일 선택(다중 선택), 시작 날짜, 종료 날짜, 세션 시작/종료 시간 입력 필드가 있습니다.

**API 호출**:
- 세션 목록: `GET /clubs/{clubId}/sessions?year=2025&month=3`
- 반복 세션 생성: `POST /clubs/{clubId}/sessions/batch` (body: `{ "dayOfWeeks": ["THURSDAY"], "startDate": "2025-03-06", "endDate": "2025-06-26", "startTime": "10:00", "endTime": "13:00", "namePattern": "정기모임" }`)

### 17-19. 웹 출석현황 페이지

**진입 조건**: 사이드바 "출석현황" 메뉴 클릭 시 진입합니다.

**표시 요소**:

상단에 세션 선택 드롭다운을 배치합니다. 선택된 세션의 요약 지표(출석/지각/결석/기타 수)를 카드로 표시합니다.

멤버 출석 현황을 테이블 형태로 표시합니다. 테이블 컬럼은 이름, 학번, 출석 상태(색상 배지), 체크인 시각, 수동 처리 여부, 사유 메모, 상태 변경 액션으로 구성됩니다. 상단에 상태별 필터와 이름/학번 검색 필드를 배치합니다.

일괄 변경을 위한 체크박스가 각 행 좌측에 있으며, 여러 행 선택 후 상단 일괄 변경 버튼 클릭 시 선택된 멤버들의 상태를 한 번에 변경하는 모달이 열립니다.

**사용자 액션**:

테이블 각 행의 상태 배지 클릭 시 해당 행 인라인으로 상태 변경 드롭다운이 활성화됩니다. 변경 즉시 API를 호출합니다. 일괄 변경 시 선택한 상태와 선택적 사유 메모를 입력합니다.

**API 호출**:
- 출석 현황 조회: `GET /clubs/{clubId}/sessions/{sessionId}/attendance`
- 상태 변경: `PATCH /clubs/{clubId}/sessions/{sessionId}/attendance/{recordId}`
- 일괄 변경: `PATCH /clubs/{clubId}/sessions/{sessionId}/attendance/batch`

### 17-20. 웹 멤버 & 통계 페이지

**진입 조건**: 사이드바 "멤버&통계" 메뉴 클릭 시 진입합니다.

**표시 요소**:

좌측 탭으로 "멤버 목록"과 "통계"를 전환할 수 있습니다.

멤버 목록 탭에는 테이블 형태로 이름, 학번, 역할, 전체 출석률, 출석/지각/결석 횟수, 역할 변경 및 제명 액션 버튼이 표시됩니다.

통계 탭에는 다음 세 가지 차트가 표시됩니다. 첫째로 기간별 출석률 추이 라인 차트(날짜 범위 선택기 포함)가 있습니다. 둘째로 멤버별 출석률 비교 가로 바 차트(출석률 높은 순 정렬)가 있습니다. 셋째로 전체 상태 분포 도넛 차트(출석/지각/결석/기타 비율)가 있습니다.

통계 탭 우측 상단에 "CSV 내보내기"와 "Excel 내보내기" 버튼을 배치합니다. 기간과 멤버를 필터링한 상태에서 내보내기 버튼 클릭 시 해당 조건으로 파일을 생성합니다.

**사용자 액션**:

날짜 범위 변경 시 모든 차트가 해당 기간 기준으로 갱신됩니다. 차트의 특정 데이터 포인트 호버 시 툴팁으로 상세 수치를 표시합니다. 내보내기 버튼 클릭 시 필터 조건 확인 모달을 거쳐 파일 다운로드가 시작됩니다.

**API 호출**:
- 멤버 목록: `GET /clubs/{clubId}/members`
- 추이 차트: `GET /clubs/{clubId}/stats/trend?startDate=...&endDate=...`
- 멤버별 비교: `GET /clubs/{clubId}/stats/members?startDate=...&endDate=...`
- 분포 차트: `GET /clubs/{clubId}/stats/distribution?startDate=...&endDate=...`
- CSV 내보내기: `GET /clubs/{clubId}/export/csv?startDate=...&endDate=...`
- Excel 내보내기: `GET /clubs/{clubId}/export/excel?startDate=...&endDate=...`
